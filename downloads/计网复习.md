## 第一章 概述

### ===OSI 参考模型（七层）=== 【重点，必考】

从下到上依次为：

| 层号 | 层名 | 数据单元 | 核心功能 |
|---|---|---|---|
| 1 | 物理层 | 比特（bit） | 接口标准、电压标准、频分/时分复用的物理实现 |
| 2 | 数据链路层 | 帧（Frame） | 封装成帧、透明传输、差错检测 |
| 3 | 网络层 | IP 数据报 | 路由选择、逻辑寻址（IP 地址），点到点通信 |
| 4 | 传输层 | 报文段（TCP）/ 用户数据报（UDP） | 端到端通信（端口到端口），可靠/不可靠传输 |
| 5 | 会话层 | — | 管理会话（未学，已合并到其他层） |
| 6 | 表示层 | — | 数据格式转换、编码解码、加密（未学，已合并） |
| 7 | 应用层 | 报文 | 各种网络应用协议（HTTP、DNS、FTP 等） |

**关键区分**：【重点】
- 传输层：**端到端**通信（端口到端口）
- 网络层：**点到点**通信（主机到主机）

> 两层之间的区别及每层对应的数据单元是常考点。提到某一层时脑中应浮现其协议和功能。

### ===各层典型设备=== 【重点】

| 层 | 典型设备 | 关键能力 |
|---|---|---|
| 物理层 | 集线器、中继器 | 信号放大/再生，广播通信 |
| 数据链路层 | 网桥、交换机、网卡 | 隔离冲突域，基于 MAC 地址转发 |
| 网络层 | 路由器 | 隔离广播域，基于 IP 地址路由选择 |
| 传输层及以上 | 网关 | 协议转换，连接异构网络 |

> 物理层设备（集线器/中继器）不能隔离冲突域；数据链路层设备（网桥/交换机）隔离冲突域但不能隔离广播域；路由器隔离广播域。常考层级归属。

### ===TCP/IP 参考模型（四层）=== 【重点】

| TCP/IP 层 | 对应 OSI 层 |
|---|---|
| 应用层 | 应用层 + 表示层 + 会话层 |
| 传输层 | 传输层 |
| 网际层 | 网络层 |
| 网络接口层 | 数据链路层 + 物理层 |

> 需记住 OSI 和 TCP/IP 各层之间的合并/对应关系。

### ===协议三要素===

**语法、语义、同步**。

### ===层层封装原理=== 【重点】

封装过程（以 HTTP 为例，从上到下）：

1. **应用层**：HTTP 报文（含 HTTP 头部 + 数据）
2. **传输层**：将 HTTP 整个报文作为 TCP 的数据部分，加上 TCP 头部 → TCP 报文段
3. **网络层**：TCP 报文段整体作为 IP 数据报的数据部分，加上 IP 首部 → IP 数据报
4. **数据链路层**：IP 数据报整体作为 MAC 帧的数据部分，加上帧头和帧尾 → MAC 帧
5. **物理层**：MAC 帧转换为比特流（0101）发送

核心规律：**每一层都将上层的整个报文作为自己的数据部分，再添加本层的头部。**

解封装过程与之相反，逐层去掉头部还原数据。

**表示层的编解码**：发送方和接收方必须使用相同的字符集，否则无法正确解析。此知识点以理解为主，最多考查一道选择题。

### ===网络性能指标===

#### 传输速率

单位时间内传输的比特数。单位：bps、Kbps、Mbps、Gbps 等（注意 bit 与 Byte 的区别，1 Byte = 8 bit）。

#### 带宽

**带宽 = 最大传输速率**。【重点】

#### 吞吐量

整条链路上的下载速率 + 上传速率之和。

### ===时延=== 【重点】

| 类型 | 含义 | 来源 |
|---|---|---|
| 发送时延 | 主机将数据发送到链路上所需的时间 | 网卡/计算机发送过程 |
| 传播时延 | 数据在链路上从起点传播到终点所需的时间 | 物理介质传播 |
| 处理时延 | 路由器对分组进行处理（如查表转发）所需时间 | 路由器"转发"功能 |
| 排队时延 | 分组在路由器缓存中排队等待处理的时间 | 路由器"存储"功能 |

**路由器核心功能：存储转发**。【重点】
- 存储 → 产生排队时延
- 转发 → 产生处理时延

> 注意区分发送时延与传播时延：发送时延是"数据上链路"的时间，传播时延是"数据在链路上走"的时间。

#### 往返时间 RTT

数据从发送方到达接收方再返回发送方的总时间。时延带宽积 = 传播时延 × 带宽。

#### 网络利用率

发送数据时间 ÷ 监测时间段。简单了解即可。

### ===网络分类===

按覆盖范围：

- **局域网（LAN）**：学校内部网络、家庭 WiFi 等
- **广域网（WAN）**：中国互联网、Internet 等

> 局域网和广域网是相对概念，不能单纯用距离划分。最大的互联网是 **因特网（Internet）**。

### 其他了解内容

- 无线路由器组件：不考
- 抓包实验：不考，仅用于体验
- 路由器配置命令：可能考

## 第二章 物理层

### ===物理层基本概念=== 【重点】

物理层有四个基本特性：

- **机械特性**：接口的物理形状、尺寸、引脚数等
- **电气特性**：电压范围、传输速率等
- **功能特性**：每个引脚的功能定义
- **过程特性**：信号时序关系

### ===模拟信号与数字信号=== 【重点】

| | 模拟信号 | 数字信号 |
|---|---|---|
| 特性 | 连续 | 离散（方波信号） |
| 抗干扰 | 弱，干扰后难以恢复 | 强，易于恢复 |
| 一个波形 | — | 一个码元 |

**方波的合成**：方波可由基波（模拟信号）加上多次简谐波叠加合成。这是信号分析的基础概念，了解即可。

### ===模数转换：调制与解调===

- **调制**：将数字信号转换为模拟信号（数模转换）
- **解调**：将模拟信号转换为数字信号（模数转换）
- **基带调制**：直接在基带上进行波形变换
- **带通调制（载波调制）**：将基带信号调制到载波上传输，常用编码方式包括**曼彻斯特编码**和**差分曼彻斯特编码**
  - **曼彻斯特编码**：每比特中间有一次跳变，位中间跳变既作时钟信号又作数据信号
  - **差分曼彻斯特编码**：位中间跳变仅提供时钟，位开始处是否有跳变表示 0 或 1（有跳变为 0，无跳变为 1），抗干扰性更强

### ===奈氏准则（Nyquist）=== 【重点】

**适用条件**：理想信道（无噪声、无干扰）

**公式**：最高码元传输速率 = 2W（Baud）

其中 W 为信道带宽（Hz）。

> 遇到"理想信道""理想低通""无干扰"等关键词 → 使用奈氏准则。

### ===香农定理（Shannon）=== 【重点】

**适用条件**：有噪声/干扰的信道

**公式**：信道极限传输速率 C = W × log₂(1 + S/N)（bps）

其中：
- W：信道带宽（Hz）
- S/N：信噪比（信号功率与噪声功率之比）

**信噪比换算**：若题目给出信噪比（dB），需先换算为 S/N：
- 信噪比(dB) = 10 × log₁₀(S/N)
- 例如：30dB → S/N = 1000

> 奈氏准则 vs 香农定理：前者给的是码元速率上限，后者给的是比特速率上限。考试中一般不会直接指定用哪个公式，需根据"理想信道"还是"有噪声"来判断。

### ===传输媒体===

**导向性传输介质**（看得见摸得着）：双绞线、同轴电缆、光纤

**非导向性传输介质**（无线）：红外线、微波、无线电波、WiFi

#### ===双绞线=== 【重点】

- 抗干扰能力弱
- 适合室内布线，不适合室外和远距离传输
- 最长 100m，超过需要中继器

线序（了解）：
- **T568B**：橙白/橙/绿白/蓝/蓝白/绿/棕白/棕
- **T568A**：将 T568B 的 1-3、2-6 互换

#### 同轴电缆

- **50Ω**：用于数字传输（基带同轴电缆）
- **75Ω**：用于模拟传输（宽带同轴电缆，如有线电视网）
- 入户一般为细缆（分支电缆）

#### 光纤

- **多模光纤**：芯径较粗，多条光路，适合短距离
- **单模光纤**：芯径极细，单一光路，适合长距离

#### ===以太网物理层标准=== 

| 名称 | 传输介质 | 网段最大长度 | 特点 |
|---|---|---|---|
| 10Base-5 | 粗同轴电缆 | 500m | 早期电缆，已废弃 |
| 10Base-2 | 细同轴电缆 | 185m | 不需要集线器 |
| 10Base-T | 非屏蔽双绞线 | 100m | 最便宜的系统 |
| 10Base-F | 光纤 | 2000m | 适合于楼间使用 |

> "10"表示速率 10Mbps，"Base"表示基带传输，后缀表示介质类型或长度。了解即可，可能出选择题。

### ===信道复用技术=== 【重点】

1. **频分复用（FDM）**：按频率不同划分信道，各用户占用不同频带。仅适用于模拟信号。
2. **时分复用（TDM）**：按时间片划分，不同用户在不同时间使用信道。
3. **统计时分复用（STDM）**：解决 TDM 的空隙浪费问题——某用户空闲时，其他用户可使用其时间片。
4. **波分复用（WDM）**：光的频分复用，用于光纤传输。
5. **码分复用（CDM）**：即码分多址 **CDMA**，抗干扰能力强。每个站被指派一个唯一的 m 比特码片序列。

### 宽带接入技术

了解即可。光纤接入技术中需知道 ADSL（非对称数字用户线）等基本概念。选择题最多出一个选项。

## 第三章 数据链路层

### ===数据链路层的三个基本问题=== 【重点】

1. **封装成帧**：在数据前后加帧头和帧尾（帧开始符 SOH / 帧结束符 EOT），将物理层传来的比特流划分成帧。
2. **透明传输**：无论数据包含什么比特组合，都能原样传输。若数据中出现与帧定界符相同的比特组合，使用**转义字符（ESC）**进行字节填充。
3. **差错检测**：检测传输过程中的误码。常用方法：**循环冗余校验（CRC）**，产生 **FCS（帧校验序列）**。

**帧**：数据链路层的数据传输单元。数据链路层将网络层交下来的 IP 数据报封装成帧。

**MTU（最大传输单元）**：以太网的 MTU = **1500 字节**。【重点】

> **MTU 的组成**：以以太网为例，MTU = 1500 字节 = IP 数据部分（约 1420 字节）+ IP 首部 + TCP 首部等开销（约 80 字节）。当数据报从 MTU 较大的链路进入 MTU 较小的链路时，需要进行分片。

#### CRC 校验与 FCS 补充说明 【重点】

- 网络是不可靠的，误码率永远不会为 0。
- 在现在的 TCP/IP 网络中，数据链路层**不负责可靠性传输**（原因是传输介质质量较好、误码率低，没必要让数据链路层承担），但必须具有**差错检测**功能。可靠传输的任务交给传输层完成。
- 数据链路层的差错检测使用 CRC 校验方法，产生 FCS（帧校验序列），FCS 是一组用于校验的冗余码。
- 由于数据在传输过程中要经过多段链路，每经一段链路数据帧都要**重新封装、重新校验**，这就要求计算 FCS 和进行 CRC 校验的速度都要尽可能快，所以**整个校验过程由硬件完成**，速度很快。

### ===PPP 协议=== 【重点】

**PPP 协议组成**：由 **HDLC**（高级数据链路控制）、**LCP**（链路控制协议）、**NCP**（网络控制协议）三部分组成。

**同步传输 vs 异步传输**：
- PPP 支持同步传输和异步传输
- 同步传输：面向比特
- 异步传输：面向字符，使用**字节填充**

**PPP 帧定界符**：头和尾均为 **7E**（十六进制）
- 7E 二进制：0111 1110
- 若数据中出现连续的 5 个 1，则在第 5 个 1 后插入一个 0（**零比特填充**），确保不会与 7E 混淆。

> 16 进制 ↔ 二进制转换必须掌握，会混在其他题中考查。

### ===广播信道的数据链路层===

- **点到点信道**：用于广域网
- **广播信道**：用于局域网

使用 **CSMA/CD** 协议的网络称为**以太网**。

### ===IEEE 802.3 / Ethernet V2 MAC 帧格式===

以太网使用 **Ethernet V2 标准**。帧格式需熟悉（教材表格），包括字段含义和长度限制。

### ===CSMA/CD 协议=== 【重点】

- 用于**总线型网络**
- 是**半双工通信**协议
- 核心机制：多点接入、载波侦听、碰撞检测

**以太网帧长度**：
- 最短帧：**64 字节**
- 最长帧（MTU）：**1500 字节**

### ===以太网帧格式补充===

- 以太网使用**曼彻斯特编码**
- 以太网帧只有帧开始定界符，**没有帧结束定界符**（与 PPP 不同）

### ===网卡=== 【重点】

网卡工作在**数据链路层和物理层**。MAC 地址烧录在网卡的 ROM 中。

**网卡功能详解**：

**物理层功能**：
- 实现与局域网传输介质之间的物理连接、电信号匹配
- 数据的编码与解码（曼彻斯特编码与译码）

**数据链路层功能**：
- 帧的发送与接收、封装与解封
- 帧的差错校验
- 介质访问控制（以太网使用 CSMA/CD 协议）
- **数据缓存功能**：计算机内部数据传输为并行（速度快），网络通信为串行（速度慢），网卡需要进行**串/并转换**并缓存数据以匹配速率差异

### ===MAC 地址=== 【重点】

- **48 位**全球唯一地址，前 24 位是**厂商号**（由专门管理机构分配，厂商需申请购买），后 24 位是**序列号**
- 烧录在网卡的 ROM 中，不可更改，是一个物理地址

**MAC 地址帧类型**：网卡收到帧后首先检查目的 MAC 地址，判断是否为发送给本站的帧：

| 类型 | 特征 | 说明 |
|---|---|---|
| 单播帧 | 目的 MAC 与本站相同，第 1 字节最低位为 **0** | 一对一通信 |
| 广播帧 | 目的 MAC 全 1（FF-FF-FF-FF-FF-FF） | 发送给网络内所有站 |
| 多播帧 | 第 1 字节最低位为 **1** | 发送给网络内部分站 |

> 注意区分：广播帧的目的 MAC 全是 1；多播帧看第 1 字节最低位是否为 1。选择题常考。

### ===集线器===

- 工作在**物理层**
- 采用**广播通信**方式
- **不能隔离冲突域**

### ===网桥=== 【重点】

- 工作在数据链路层
- 能够根据 MAC 地址过滤和转发帧
- **隔离冲突域**（与交换机相同）

### ===交换机===

- 工作在数据链路层
- 多端口网桥，全双工通信
- **不使用 CSMA/CD 协议**
- **隔离冲突域**

### ===冲突域与广播域=== 【重点】

- **网桥和交换机隔离冲突域**
- **路由器隔离广播域**

### 吉比特以太网

了解 1000BASE-T 等标准的基本概念即可。

## 第四章 网络层

> 网络层内容非常多，除 RIP/OSPF 等路由协议外，几乎全是重点。

### ===IP 地址与子网划分=== 【重点】

#### IP 地址分类

| 类别 | 网络号范围 | 默认掩码 | 特点 |
|---|---|---|---|
| A 类 | 1 ~ 126 | 255.0.0.0 | 第一个字节固定为网络号 |
| B 类 | 128 ~ 191 | 255.255.0.0 | 前两个字节为网络号 |
| C 类 | 192 ~ 223 | 255.255.255.0 | 前三个字节为网络号 |
| D 类 | 224 ~ 239 | — | 多播地址 |
| E 类 | 240 ~ 255 | — | 保留 |

**特殊地址**：
- **127.x.x.x**（如 127.0.0.1）：回环地址（Loopback）
- 主机号全 0：网络地址
- 主机号全 1：广播地址

#### 子网掩码（Subnet Mask）

- 区分 IP 地址中的**网络部分**和**主机部分**，看的是**掩码**。
- 掩码中为 1 的位对应网络部分，为 0 的位对应主机部分。

#### CIDR（无分类域间路由）与子网划分

CIDR 将主机号的一部分借用作子网号。

**子网划分计算步骤**：【重点】

1. 根据 IP 地址第一个字节判断属于哪类地址（A/B/C）
2. 确定该类地址的默认掩码
3. 将实际掩码与默认掩码对比，找出被借用作子网号的位数 n
4. 子网数 = 2^n（CIDR 全 0 全 1 均可用）
5. 主机数 = 2^(剩余主机位数) - 2（减去全 0 网络地址和全 1 广播地址）

**示例**：IP 地址 128.11.34.12，掩码 255.255.192.0
- 128 开头 → B 类地址，默认掩码 255.255.0.0
- 第三字节 192 = 11000000，前 2 位被借用 → n = 2
- 子网数 = 2² = 4 个
- 子网号：00、01、10、11
- 主机位 = 6 + 8 = 14 位，主机数 = 2¹⁴ - 2

### NAT（网络地址转换）

将内网（私网）地址和端口转换为公网地址和端口。常见内网地址段：10.x.x.x、172.16~31.x.x、192.168.x.x。

### ===网络层核心功能===

**网络层为传输层提供简单灵活、无连接、尽最大努力交付的数据报服务。**每个分组独立选择路径，不保证可靠性。【重点】

### 网络畅通条件

- 有去有回：正常转发
- 无法到达：unreachable
- 有去无回：dead end

### ===静态路由与动态路由===

#### 静态路由配置命令

`ip route <目标网络> <掩码> <下一跳地址>`

#### 默认路由

- 目标网络和掩码均为 0.0.0.0
- 用途：路由表中无匹配项时，将数据包发往默认路由的下一跳
- 添加命令：`route add 0.0.0.0 mask 0.0.0.0 <下一跳>`

#### 路由汇总

将多个子网的路由合并为一条，取 IP 地址中前面共同的 1 位。

### ===RIP 协议=== 【重点】

- 属于**距离矢量**路由协议
- 网络不可达跳数：**16 跳**
- 仅适用于**小型网络**
- 配置命令：`network <网络地址>`
- 路由表查看：`show ip route`

### ===OSPF 协议===

- 全称：**开放最短路径优先**协议
- 基于链路状态，通过路径开销判断最优路由
- 维护**链路状态数据库（LSDB）**
- 分区域管理
- 五种报文类型（了解即可）

**RIP 与 OSPF 路由表区别**：开头标记不同，其余格式类似。

### ===IP 数据报首部格式=== 【重点】

需记忆以下字段及其长度：

| 字段 | 位数 | 说明 |
|---|---|---|
| 版本 | 4 位 | IPv4 / IPv6 |
| 首部长度 | 4 位 | 单位 4 字节 |
| 总长度 | 16 位 | 单位 1 字节 |
| 标识 | 16 位 | 用于分片重组 |
| 标志 | 3 位 | 最高位保留，DF（不分片），MF（更多分片） |
| 片偏移 | 13 位 | 单位 8 字节 |
| 生存时间（TTL） | 8 位 | 防止数据包在网络中无限循环 |
| 协议 | 8 位 | 上层协议类型 |
| 源 IP 地址 | 32 位 | — |
| 目的 IP 地址 | 32 位 | — |

> **记忆口诀：总一首四偏八** —— 总长度 ×1、首部长度 ×4、片偏移 ×8 才是实际字节数。

### ===分片=== 【重点】

**概念**：当 IP 数据报从 MTU 较大的链路进入 MTU 较小的链路时，需将数据报分成多个较小的分片。

**相关字段**：标识、标志（DF/MF）、片偏移

- **片偏移**：当前分片在原数据报中的相对位置，**片偏移数值 ×8 才是具体偏移的字节数**。

### TTL（生存时间）

数据包每经过一个路由器 TTL 减 1，减到 0 时数据包被丢弃。用于防止数据包在网络中无限循环。

### ===ICMP 协议=== 【重点】

- 全称：**Internet 控制报文协议**
- 封装在 IP 数据报中传输
- 用于测试网络连通性
- 两个常用命令：
  - **ping**：测试主机是否可达
  - **tracert（traceroute）**：探测到达目标主机的路径

### ARP 协议

将 IP 地址解析为 MAC 地址。

### ===ARP 欺骗=== 

**ARP 欺骗原理**：攻击者伪造 ARP 应答报文，将网关的 IP 地址映射到错误的 MAC 地址（攻击者的 MAC），使受害主机的数据包发往攻击者而非真正的网关。攻击者由此可窃听、篡改通信数据。

**防范方法**：
1. 使用 `arp -a` 命令查看 ARP 映射表，核对网关 IP 对应的 MAC 地址是否正确
2. 使用 `arp -s <网关IP> <网关MAC>` 命令绑定静态 ARP 表项，防止被动态更新覆盖

### IGMP 协议

Internet 组管理协议，用于多播，了解即可。

## 第五章 传输层

### ===TCP 与 UDP 对比=== 【重点】

| | TCP | UDP |
|---|---|---|
| 连接方式 | 面向连接 | 无连接 |
| 可靠性 | 可靠传输 | 尽最大努力交付 |
| 首部开销 | 大（20 字节） | 小（8 字节） |
| 适用场景 | 文件传输、Web、邮件 | 视频直播、语音通话、DNS |
| 通信方式 | 一对一（点对点） | 一对一、一对多、多对多 |
| 流量控制 | 有 | 无 |
| 面向方式 | 面向字节流 | 面向报文 |

### 端口号分类

- **熟知端口**（0 ~ 1023）：如 HTTP 80、DNS 53
- **注册端口**（1024 ~ 49151）
- **动态/私有端口**（49152 ~ 65535）

### UDP 特点

- 无连接
- 尽最大努力交付
- 面向报文
- 无拥塞控制
- 支持一对一、一对多、多对多通信
- 首部仅 8 字节

**UDP 伪首部**：用于校验和计算，既不向下递交也不向上递交，仅在校验时临时使用。

### TCP 特点

- 面向连接的传输层协议
- 点对点（一对一）
- 提供可靠交付
- 全双工通信
- 面向字节流

### TCP 首部重要字段

| 标志位 | 含义 |
|---|---|
| URG | 紧急指针有效 |
| ACK | 确认号有效 |
| PSH | 推送 |
| RST | 重置连接 |
| SYN | 同步序号（用于连接建立） |
| FIN | 终止连接 |

### ===TCP 三次握手=== 【重点】

**三次握手过程**：

1. **第一次握手**：客户端 → 服务器，SYN = 1，ACK = 0，seq = x
   - 作用：客户端告知服务器"我要建立连接"
2. **第二次握手**：服务器 → 客户端，SYN = 1，ACK = 1，seq = y，ack = x + 1
   - 作用：服务器确认收到，并告知客户端"我已准备好"
3. **第三次握手**：客户端 → 服务器，ACK = 1，seq = x + 1，ack = y + 1
   - 作用：客户端告知服务器"我知道你准备好了，接下来开始传输"。**第三次握手让服务器确认：客户端能够正常发送数据，双方的收发通道均正常。**

**为什么需要三次握手（而非两次）**：两次握手只能让客户端确认服务器在线，但服务器不知道客户端是否知道自己已准备好。第三次握手让服务器确认：客户端已收到自己的确认，即将开始发送数据。

### TCP 四次挥手

1. 客户端 → 服务器：FIN = 1，seq = u（关闭连接请求）
2. 服务器 → 客户端：ACK = 1，seq = v，ack = u + 1（确认收到关闭请求）
3. 服务器 → 客户端：FIN = 1，ACK = 1，seq = w，ack = u + 1（服务器也发送关闭请求）
4. 客户端 → 服务器：ACK = 1，seq = u + 1，ack = w + 1（最终确认）

### ===可靠传输机制===

#### 停止等待协议

- A 发送一个分组后停止发送，等待 B 的确认（ACK）
- 收到 ACK 后才发下一个分组
- **超时重传**：若超时未收到 ACK，A 自动重传。【重点：可靠传输的根基】
- ACK 丢失 → A 超时重传，B 收到重复分组后丢弃但重申 ACK
- 分组丢失 → 同上，超时重传

#### 连续 ARQ 协议与滑动窗口

- 发送方可连续发送多个分组而不必等待确认
- 发送窗口大小由接收方的窗口字段决定
- **序号**：当前发送分组在本端的序号（系统分配的起始值）
- **确认号（小 ack）**：期望接收的下一个分组的序号

### ===流量控制===

- 控制对象：**发送方的发送窗口大小**
- 控制依据：接收方在 TCP 首部"窗口"字段告知自己还能接收的数据量
- 控制目的：防止发送方发送过快导致接收方来不及处理

### ===拥塞控制=== 【重点】

拥塞控制与发送方、接收方**都无关**，针对的是**收发双方之间的网络状况**。

**四个算法**：

1. **慢开始**：初始拥塞窗口很小，指数增长
   - 触发条件：连接刚开始，或发生**超时**
2. **拥塞避免**：达到慢开始门限后，线性增长
3. **快重传**：收到 **3 个重复 ACK** 时立即重传丢失的分组
4. **快恢复**：收到 3 个重复 ACK 时不进入慢开始，而是将**门限减半**后直接进入拥塞避免阶段

**慢开始门限（ssthresh）**：
- 初始值由系统设定
- 发生网络拥塞后，新门限 = 当前拥塞窗口值的一半

## 第六章 应用层

### ===DNS（域名系统）===

#### 域名层级

对于一个完整域名（如 `www.example.com`）：
- 顶级域名：com
- 二级域名：example
- 三级域名：www

#### DNS 解析过程（迭代查询）【重点】

1. 主机向本地 DNS 服务器发送域名解析请求
2. 本地 DNS 服务器向**根域名服务器**查询，返回顶级域名服务器的 IP
3. 本地 DNS 服务器向**顶级域名服务器**查询，返回二级域名服务器的 IP
4. 本地 DNS 服务器向**二级域名服务器**查询，返回三级域名服务器的 IP
5. 逐级查询，直至获得该域名对应的最终 IP 地址

**DNS 使用的传输层协议**：UDP（端口 53）。在区域传送时使用 TCP。

### ===FTP（文件传输协议）===

- 使用两个并行 TCP 连接：
  - **控制连接**：端口 **21**，用于传输命令
  - **数据连接**：端口 **20**，用于传输数据
- 两种模式：
  - **主动模式**：服务器主动连接客户端的数据端口
  - **被动模式**：客户端连接服务器开放的数据端口

### DHCP

动态主机配置协议，用于自动分配 IP 地址。了解即可。

### Telnet

远程终端协议，使用 **TCP 端口 23**。

### HTTP

超文本传输协议，使用 **TCP 端口 80**。HTTPS 使用 **TCP 端口 443**。

### 电子邮件协议

- **SMTP**：简单邮件传输协议，用于发送邮件，TCP 端口 25
- **POP3**：邮局协议第三版，用于接收邮件，TCP 端口 110

### 应用层协议汇总

| 协议 | 传输层协议 | 端口号 |
|---|---|---|
| DNS | UDP（查询）/ TCP（区域传送） | 53 |
| FTP（控制） | TCP | 21 |
| FTP（数据） | TCP | 20 |
| Telnet | TCP | 23 |
| HTTP | TCP | 80 |
| HTTPS | TCP | 443 |
| SMTP | TCP | 25 |
| POP3 | TCP | 110 |
